### [2026-04-06] Превышен лимит Vercel: 14 функций вместо 12
- **Категория:** Деплой
- **Симптом:** Build Failed на Vercel, деплой не проходит
- **Причина:** Vercel Hobby план допускает максимум 12 Serverless Functions. Три отдельных файла аналитики (`api/analytics/view.js`, `api/analytics/user.js`, `api/admin/analytics.js`) выводили за лимит.
- **Решение:** Объединили три файла в один `api/analytics.js` с маршрутизацией по методу и query-параметру (`?type=view`, `?type=user`). GET-запрос — для админа, POST — публичный.
- **Файлы:** `api/analytics.js` (новый), удалены три старых файла
- **Статус:** ✅ Исправлено

### [2026-04-06] Двойной `/м` в цене: "5,30 уе./м/м"
- **Категория:** Фронтенд
- **Симптом:** Цена отображалась как "5,30 уе./м/м" вместо "5,30 уе./м"
- **Причина:** Функция `formatPrice()` уже возвращала строку с `/м` внутри, а шаблоны в `app.js` дополнительно добавляли `/м` после вызова функции.
- **Решение:** Убрали явный `/м` из всех шаблонов в `app.js`. Единица измерения формируется только внутри `formatPrice(num, unit)`.
- **Файлы:** `tg-app/js/data.js`, `tg-app/js/app.js`
- **Статус:** ✅ Исправлено

---

### [2026-04-06] Ошибка CHECK constraint при сохранении ткани
- **Категория:** БД
- **Симптом:** При нажатии «Сохранить» в карточке ткани — ошибка 400: `new row for relation "fabrics" violates check constraint "fabrics_unit_check"`
- **Причина:** Constraint `CHECK (unit IN ('м', 'кг'))` был создан через Supabase Management API с кириллицей, которая сохранилась в неправильной кодировке. Значения из JS ('м', 'кг' в UTF-8) не совпадали с тем, что хранилось в constraint.
- **Решение:** Удалить constraint через Supabase SQL Editor. Валидация значений уже есть на уровне API (`api/admin/fabrics.js`), DB-constraint избыточен.
  ```sql
  ALTER TABLE fabrics DROP CONSTRAINT fabrics_unit_check;
  ```
- **Файлы:** Только Supabase (DDL), код не менялся
- **Статус:** ✅ Исправлено

### [2026-04-06] Плавающая точка в snapToStep: 0.5 + 0.1 = 0.6000000000001
- **Категория:** Фронтенд
- **Симптом:** При шаге 0.5 счётчик показывал некорректные значения с кучей знаков после запятой
- **Причина:** Стандартная проблема floating-point в JavaScript: арифметика с дробными числами даёт погрешность.
- **Решение:** В `snapToStep()` вычисляем количество знаков после запятой у шага и применяем `.toFixed(precision)` к результату.
  ```js
  const precision = (s.toString().split('.')[1] || '').length;
  return Math.max(m, parseFloat(snapped.toFixed(precision)));
  ```
- **Файлы:** `tg-app/js/data.js`
- **Статус:** ✅ Исправлено

## Быстрая диагностика

**Ошибка в браузере при сохранении (400/500):**
1. Открыть DevTools → Network → найти упавший запрос → смотреть Response
2. Ошибка Supabase — скорее всего проблема в структуре данных или constraint в БД
3. Ошибка 401 — не прошла авторизация, проверить ADMIN_SECRET

**Изменения не отображаются после деплоя:**
1. Vercel Dashboard → Deployments — проверить статус билда
2. Если Build Failed — смотреть лог, скорее всего лимит функций или синтаксическая ошибка
3. Если Deployed — очистить кэш браузера (Ctrl+Shift+R)

**Telegram Mini App не открывается:**
1. Проверить что бот настроен (`/setmenubutton` в BotFather)
2. Проверить что URL в настройках бота указывает на правильный домен Vercel
