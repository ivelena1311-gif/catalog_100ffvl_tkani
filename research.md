# Исследование: Telegram Mini Apps для каталога оптовой продажи тканей

> Исследование проведено тремя параллельными агентами. Ниша Telegram Mini Apps для
> оптовых тканей **практически пустая** — это сильное конкурентное преимущество.

---

## 5 примеров Telegram Mini Apps в смежных нишах

---

### Пример 1 — Бот-каталог оптового поставщика одежды

**Что делает:** Пользователь выбирает категорию через inline-кнопки → видит фото
товаров → узнаёт цену → пишет менеджеру. Типичные боты ивановских, белорусских и
турецких производителей трикотажа и одежды оптом.

**Сильные стороны:**
- Быстрый вход без регистрации — нажал /start и уже в каталоге
- Фото товаров прямо в чате — нативный просмотр без перехода на сайт
- Указание цены за единицу и минимальной партии
- Можно переслать карточку товара коллеге одним движением
- Кнопка "Написать менеджеру" — прямой переход в диалог

**Слабые стороны:**
- Нет фильтрации вообще — ни по цвету, ни по составу, ни по размеру
- Пагинация через /следующий неудобна, теряется контекст
- Нет корзины — нельзя накопить список позиций для заявки
- Нет поиска по артикулу или наименованию
- Одно фото на товар, без зума, фактуру не видно
- Нет актуальных остатков — всегда "уточняйте наличие"

**Что мы можем сделать лучше:**
- Mini App с полноценной галереей и зумом для просмотра фактуры ткани
- Фильтры: состав, ширина полотна, плотность (г/м²), цвет, страна производства
- Корзина с накоплением позиций и формированием заявки
- Остатки в реальном времени (метры/рулоны, не просто "в наличии")

### Пример 2 — Telegram Mini App фурнитурного оптовика (каталог-витрина)

**Что делает:** Полноценное веб-приложение внутри Telegram. Поставщики швейной
фурнитуры (молнии, пуговицы, ленты, нитки) строят такие приложения на конструкторах
(Ecwid, Sellty) или кастомном React. Открывается кнопкой "Открыть каталог" в боте.

**Сильные стороны:**
- Полноценный интерфейс магазина: карточки, сетка, корзина, поиск
- Интеграция с Telegram Payments — оплата прямо в приложении
- Несколько фото в карточке, выбор цвета/размера через chips
- Категории с иконками, поиск по названию
- Работает быстрее мобильного сайта, ощущается как нативное приложение

**Слабые стороны:**
- Медленная загрузка при слабом интернете (Mini App загружает весь сайт)
- Нет B2B-логики: все видят одну и ту же цену, нет оптовых уровней
- Авторизация оптового клиента не предусмотрена
- Нет возможности запросить образец перед партией
- История заказов не работает — нужно писать менеджеру
- Каталог не синхронизирован с реальным складом

**Что мы можем сделать лучше:**
- Система ценовых уровней: "Розница / Мелкий опт / Крупный опт" по метражу
- Кнопка "Запросить образец" с указанием адреса
- Живые остатки из склада через API или webhook
- Верификация оптового клиента для открытия оптовых цен

### Пример 3 — Связка "Telegram-канал + бот-витрина" (домашний текстиль, Иваново)

**Что делает:** Публичный канал публикует фото новинок постельного белья и
полотенец с ценами → бот принимает заказ по артикулу из поста. Широко
распространено среди производителей домашнего текстиля.

**Сильные стороны:**
- Канал работает как витрина: подписчики видят новинки в ленте автоматически
- Высокая скорость публикации новых поступлений
- Живая аудитория с реакциями — социальное доказательство работает
- Бот быстро собирает заявку: "Артикул — количество — адрес — контакт"
- Нулевые затраты на хостинг и разработку

**Слабые стороны:**
- Нет структурированного каталога — найти нужный артикул через историю канала
  невозможно
- Встроенный поиск Telegram ищет плохо даже по своим каналам
- Фото теряются в хронологии — спустя месяц не найти
- Бот не помнит предыдущих заказов — нет CRM-логики
- Нет уведомлений о статусе заказа
- Нет автоматической проверки наличия перед подтверждением заявки

**Что мы можем сделать лучше:**
- Mini App как постоянный структурированный каталог в дополнение к каналу
- Умный поиск по тегам: #лён #140см #белый #летний
- Автоматические уведомления об изменении остатков на популярные позиции
- Личный кабинет с историей заказов и накопленным объёмом для скидки

### Пример 4 — B2B-каталог строительных материалов для дилеров

**Что делает:** Полноценный Telegram Mini App для оптовых закупщиков
стройматериалов. Показывает цены только авторизованным дилерам, включает
историю заказов и калькулятор расхода материала.

**Сильные стороны:**
- Цены скрыты от розницы — показываются только после авторизации по Telegram ID
- В карточке: розничная цена перечёркнута, оптовая выделена акцентом
- Минимальный заказ и кратность упаковки указаны прямо на карточке
- История заказов с кнопкой "Повторить заказ" — критично для постоянных клиентов
- Tab Bar внизу: Каталог / Избранное / Корзина / Профиль
- В профиле: данные компании, персональный менеджер, кредитный лимит

**Слабые стороны:**
- Долгий цикл сделки не поддержан — всё заканчивается на "напишите менеджеру"
- Нет сравнения позиций
- Нет функции "Избранное" для сохранения частых позиций
- Документы (счета, накладные) не генерируются в боте
- Каталог не интегрирован с 1С в реальном времени

**Что мы можем сделать лучше:**
- Добавить "Избранное" и сравнение — для ткани критично сравнить два артикула
- Генерация предварительной заявки → PDF прямо из корзины
- Калькулятор метража в зависимости от объёма закупки и скидки
- Сезонные коллекции как отдельный раздел с предзаказом

### Пример 5 — Боты китайских посредников (ткани с 1688/Taobao → РФ)

**Что делает:** Боты агентов по закупке тканей и фурнитуры из Китая. Клиент
кидает ссылку с 1688, бот считает стоимость с доставкой и таможней, принимает
заявку. Реально работающий сегмент с тысячами активных пользователей.

**Сильные стороны:**
- Автоматизирует рутину: расчёт стоимости, конвертация валюты, таможня
- Некоторые боты поддерживают Telegram Payments — оплата прямо в приложении
- Статусы заказа прямо в боте (принят / на складе в Китае / в пути / доставлен)
- Поддержка нескольких валют (CNY / USD / RUB)

**Слабые стороны:**
- Нет визуального каталога — работают только со ссылками, не со своим ассортиментом
- Нет поиска по артикулу внутри бота
- Интерфейс технический и сухой, не адаптирован для конечного покупателя
- Нет информации о составе, плотности, ширине ткани — только ссылка
- Длинный цикл: от заявки до получения 3–6 недель, бот не упрощает ожидание

**Что мы можем сделать лучше:**
- Собственный структурированный каталог с фото и параметрами — принципиально другой UX
- Мгновенное подтверждение наличия (товар у нас на складе в России)
- Параметры каждой ткани: состав, ширина, плотность — всё в карточке
- Быстрый заказ без недель ожидания

## Стандартные экраны каталог-приложения

```
1. Splash / Loading       — логотип + загрузка данных
2. Главная (Home)         — баннеры акций, категории, хиты, новинки
3. Каталог (Catalog)      — сетка/список + фильтры + сортировка
4. Карточка товара        — галерея фото, параметры ткани, добавление в корзину
5. Поиск (Search)         — строка поиска, результаты по артикулу/названию
6. Корзина (Cart)         — список позиций с метражом, итоговая сумма
7. Оформление заявки      — контакты, адрес доставки, комментарий
8. История заказов        — список заявок, статусы, кнопка "Повторить"
9. Профиль (B2B)          — данные компании, персональный менеджер, реквизиты
10. Избранное             — сохранённые позиции для быстрого доступа
```

## Обязательные элементы для каталога тканей

### Карточка товара — специфика ткани

| Параметр | UI-элемент | Приоритет |
|---|---|---|
| Артикул | мелкий текст под названием | MUST HAVE |
| Состав (100% хлопок) | chips / badge | MUST HAVE |
| Ширина полотна (140 см) | иконка + цифра | MUST HAVE |
| Плотность (г/м²) | иконка + цифра | MUST HAVE |
| Цвет / расцветка | цветные свотчи (кружки) | MUST HAVE |
| Оптовая цена за метр | крупно, акцентный цвет | MUST HAVE |
| Остаток (метры/рулоны) | точное число, не "в наличии" | MUST HAVE |
| Минимальный заказ | "от 10 м" | MUST HAVE |
| Кратность | "кратно 5 м" | MUST HAVE |
| Макрофото фактуры | swiper-галерея с зумом | MUST HAVE |

### Фильтры

| Фильтр | Тип UI |
|---|---|
| Тип ткани (трикотаж / ткань / кружево) | чекбоксы |
| Состав (хлопок, вискоза, полиэстер…) | мультивыбор chips |
| Ширина полотна | ползунок диапазона |
| Плотность (г/м²) | ползунок диапазона |
| Цвет | цветовая палитра свотчей |
| Цена за метр | ползунок диапазона |
| Только в наличии | чекбокс |
| Страна / производитель | выпадающий список |

### B2B-логика — критично для оптового покупателя

| Функция | Обоснование |
|---|---|
| Цены скрыты до верификации | защита от розничных цен, серьёзность подхода |
| Ценовые уровни по метражу | цена от 10 м / от 50 м / от 100 м — стандарт оптовика |
| Кратность автопересчитывается | ввёл 23 м → автоматом стало 25 м (кратно 5) |
| "Отправить заявку" вместо "Оплатить" | оптовик платит по счёту, не картой |
| Персональный менеджер в профиле | имя + телефон, прямой переход в чат |
| Повтор предыдущего заказа | постоянные клиенты закупают одно и то же |
| Запрос образца одной кнопкой | стандарт отрасли перед крупной партией |

### Навигация

**Рекомендуемый паттерн — Tab Bar внизу (4 вкладки) + нативный BackButton Telegram:**

```
[ Каталог ]  [ Поиск ]  [ Корзина (3) ]  [ Профиль ]
```

- BackButton Telegram для навигации внутри разделов (нативно, бесплатно)
- MainButton Telegram для главного CTA (фиксированная кнопка "Отправить заявку")
- CloudStorage Telegram для сохранения корзины без авторизации

| Одна цена для всех | Ценовые уровни по объёму закупки |

## Визуальные и технические рекомендации

### Цветовая схема для текстильного каталога

```css
/* Использовать CSS-переменные Telegram для поддержки тёмной темы */
background-color: var(--tg-theme-bg-color);
color: var(--tg-theme-text-color);

/* Акценты — нейтральные тёплые тона (ассоциация с тканями) */
--accent: #8B6914;       /* золотистый / бронзовый */
--price: #C0392B;        /* красный для цены */
--available: #27AE60;    /* зелёный для "в наличии" */
--secondary-bg: #FAFAF8; /* тёплый белый фон карточек */
```

### Типографика

```
Название товара:  16px, weight 600
Артикул:         12px, weight 400, secondary color
Цена (опт):      20px, weight 700, accent color
Параметры:       14px, weight 400
Кнопка CTA:      16px, weight 600
```

### Технический стек (рекомендация)

```
Frontend: React 18 + TypeScript + Vite
Стили:    CSS Modules или Tailwind (purge для малого бандла)
State:    Zustand (для корзины и фильтров)
Router:   React Router v6 (hash mode для статик-хостинга)
TG SDK:   @twa-dev/sdk
Галерея: Swiper.js
Цель:     бандл < 200KB gzipped
```

## Экспертная оценка

> Оценка с трёх точек зрения: UX-дизайнер, маркетолог, Telegram-разработчик.

---

### Взгляд UX-дизайнера

#### Типичные ошибки новичков

**Перегруз карточки товара**
- Выводят все 12 параметров сразу, без иерархии — пользователь не понимает, что главное
- Артикул ставят первым, хотя он нужен только на этапе заказа, не при выборе

**Фильтры-невидимки**
- Делают фильтры модальным окном, которое закрывается после каждого выбора
- Не показывают количество товаров при изменении фильтра — жмёшь "Применить" и видишь пустой список

**Цветовые свотчи — самая частая ошибка**
- Делают свотчи 16×16px — на телефоне это пыль, а не цвет (минимум 32×32px)
- Делают отдельную карточку на каждый цвет одной ткани: каталог из 800 позиций вместо 80

**Поиск "для галочки"**
- Поиск только по названию, без артикула и состава
- Нет нечёткого поиска (хлопок / хлопёк / cotton)

**Корзина как у B2C**
- "Количество: 1 шт" вместо метров/рулонов
- Проверка на кратность появляется только при оформлении, а не при вводе

#### Что обязательно должно быть

- **Остаток прямо в списке** — "142 м / 3 рул" в одну строку, не только в карточке
- **Ценовая сетка на карточке** — таблица: 50–99м → X руб/м, 100–299м → Y руб/м, 300м+ → Z руб/м
- **Валидация кратности в корзине** — счётчик прыгает по 10, а не принимает любое число
- **Быстрый ввод метража** — прямой ввод числа, не только кнопки ±
- **Сравнение тканей** — хотя бы 2–3 позиции рядом (подкладка, дублерин)
- **Повтор заказа** — кнопка "Повторить заказ" в истории (B2B закупают одно и то же)
- **Статус заявки** — "Принята / В обработке / Подтверждена / Отправлена"

#### Что бесит пользователей (антипаттерны)

- **Регистрация до просмотра каталога** — оптовик уйдёт. Каталог сразу, регистрация — только при добавлении в корзину
- **Фильтры сбрасываются при возврате назад** — зашёл в карточку, вернулся — фильтры слетели, список с начала
- **Нет pinch-to-zoom на фото** — фактуру ткани нельзя рассмотреть = нет продажи
- **Поп-ап "добавлено в корзину" перекрывает контент** — достаточно тихого toast и изменения иконки
- **Длинная форма оформления** — все реквизиты сразу. Разбейте на шаги или тяните из профиля
- **Пустой экран без объяснений** — фильтр дал 0 результатов, экран просто пустой

#### Правильная иерархия карточки товара

```
1. Фото-галерея (pinch-to-zoom)
2. Название + артикул (мелко, рядом)
3. Состав | Ширина | Плотность (три параметра-чипа в одну строку)
4. Цветовые свотчи (≥32×32px, лейбл при тапе)
5. Остаток: 142 м / 3 рул [бейдж "Мало" если < 50м]
6. Ценовая сетка (по умолчанию свёрнута, раскрывается тапом)
7. Мин. заказ: 50 м, кратность: 10 м
8. [Добавить к заявке]  [Запросить образец]  [В избранное]
```

#### Приоритет экранов (от важного к менее важному)

| # | Экран | Почему |
|---|---|---|
| 1 | Карточка товара | Точка принятия решения — отвечает на все вопросы без звонка |
| 2 | Каталог + фильтры | Первое впечатление, навигация к нужному товару |
| 3 | Корзина | Здесь ломается большинство B2B-флоу (кратность, минималка, итог) |
| 4 | Поиск | Оптовик знает артикул — поиск это shortcut |
| 5 | История заказов | Retention-механика, повтор заказа |
| 6 | Оформление заявки | Максимально короткий, данные из профиля |
| 7 | Профиль | Важен, но не срочен на MVP |
| 8 | Избранное | Приятно иметь, корзина частично заменяет |

> **Главная страница с баннерами для B2B почти не нужна.** Лучше сразу открывать Каталог — честнее и быстрее.

### Взгляд маркетолога

#### Что заставит оптовика открыть и остаться

**Триггеры первого визита:**
- Пост в канале поставщика: *"Поступил трикотаж — 47 артикулов, остатки живые, цена от 10м"* + кнопка прямо в посте
- QR-код на образцах ткани или в коммерческом предложении
- Личное сообщение менеджера: *"Открой каталог — там уже актуальные остатки"*
- Реферал от коллеги ("Смотри, тут нормально фильтруется по составу")

**Удержание в первые 30 секунд:**
- Показывать живой остаток и цену сразу, без регистрации
- Pinch-to-zoom на фото — оптовик зависает на 2 минуты, рассматривая фактуру
- Фильтр: нажал "хлопок + 200г/м² + от 50м" → 12 позиций вместо 400

#### Элементы, повышающие конверсию в заявку

- **Тревожный счётчик остатков** — "Осталось 230м — хватит на ~460 единиц" / "Последние рулоны"
- **Калькулятор в карточке** — "Сколько единиц изделий?" → считает нужный метраж + стоимость + скидку
- **Прогрессивное ценообразование визуально** — не просто таблица, а выделение активного уровня:
  `[ 10м — 890р/м ] [ →50м — 810р/м ] [ 100м — 740р/м ← вы здесь ]`
- **Запрос образца как отдельная CTA** — "Заказать образец — бесплатно при заказе от 50м"
- **Быстрая заявка** — кнопка "Написать менеджеру по этой позиции" → чат с предзаполненным текстом
- **Избранное с уведомлением** — "Добавить в список ожидания" если ткань закончилась

#### Механики удержания и повторных покупок

- **История заказов с повтором в один клик** — "Вы брали это в феврале — повторить заявку?"
- **Персональные подборки от менеджера** — клиент получает уведомление с уже отфильтрованным каталогом
- **Таргетированные уведомления** — "Поступил хлопок 180г/м² — вы интересовались в марте"
- **Накопительные условия без геймификации** — "При обороте от 200 000р/мес — персональная цена"

#### Сигналы доверия для B2B

- **Юридическое лицо и реквизиты** — видны сразу, не спрятаны. ИНН, ОГРН, работа с НДС
- **Сертификаты прямо в карточке** — кнопка "Скачать сертификат" (ГОСТ, OEKO-TEX)
- **Фото реального склада** — не рендеры, а живые фото с рулонами и маркировкой
- **Отзывы в формате кейсов** — "Фабрика 'Силуэт', Иваново — работаем 2 года, 14 поставок, 0 рекламаций"
- **Имя и фото менеджера** — не "Менеджер №3", а "Алексей Воронов, в тканях с 2011 года" + ссылка на TG
- **Время обновления остатков** — "Обновлено 2 часа назад" снимает страх купить то, чего нет

#### Антипаттерны, убивающие конверсию

- **Регистрация до каталога** — закроет приложение
- **Цены "по запросу"** — сигнал непрозрачности, оптовик уходит к тому, у кого цена понятна сразу
- **Форма заявки из 10+ полей** — ИНН, КПП, ОГРН, ФИО, должность для первого контакта
- **Нет ответа более 2 часов** — нужны чёткие часы работы и автоответ с временем реакции
- **"Остаток: 47 единиц"** вместо "47 рулонов / ~2350м" — всегда переводи в метры

#### Конкретные формулировки

**Кнопки:**

### Взгляд Telegram-разработчика

#### Ограничения платформы

**Критические:**
- **CloudStorage лимит: 1024 ключа, значение ≤ 4096 байт** — корзина с 50+ позициями туда не влезет
- **initDataUnsafe небезопасен на клиенте** — верификация HMAC обязательна на сервере
- **Pinch-zoom галереи конфликтует с нативным скроллом на iOS** — Swiper zoom требует настройки
- **Нет push-уведомлений** из TMA напрямую (только через бота отдельно)
- **Горизонтальный свайп недоступен** — Telegram сам свайпает для закрытия приложения
- **iOS Safe Area** — нижняя панель перекрывает контент без `padding-bottom: env(safe-area-inset-bottom)`

#### Что работает хорошо — используй на максимум

- **MainButton** — идеален для "Добавить к заявке" / "Оформить". Нативный, не занимает место в вёрстке
- **HapticFeedback** — на добавление в корзину, на ошибку, на успешную заявку
- **Telegram-авторизация через initData** — не нужен отдельный OAuth, user_id = готовая идентификация
- **CloudStorage** — хорош для небольших данных: список ID избранного, последние фильтры
- **themeParams** — автоматически адаптирует цвета под светлую/тёмную тему пользователя
- **`expand()`** — вызывать сразу при старте, пользователи ожидают полноэкранный режим

#### Что лучше не делать в TMA

- **Не используй `window.history.pushState` напрямую** — конфликтует с BackButton, только через React Router
- **Не делай горизонтальный свайп между разделами** — Telegram закроет приложение
- **Не делай модальные окна поверх модальных** — BackButton сходит с ума
- **Не загружай все изображения сразу** — 200 тканей с фото убьют память на мобиле
- **Не используй `alert()`/`confirm()`** — не работают в Desktop Telegram. Только `WebApp.showPopup()`

#### Ключевые технические решения

**BackButton — один обработчик на всё приложение:**
```typescript
// Layout.tsx — один раз, централизованно
export function Layout() {
  const navigate = useNavigate();
  const location = useLocation();

  useEffect(() => {
    const isRoot = location.pathname === '/catalog';
    isRoot ? WebApp.BackButton.hide() : WebApp.BackButton.show();
    const handleBack = () => navigate(-1);
    WebApp.BackButton.onClick(handleBack);
    return () => WebApp.BackButton.offClick(handleBack);
  }, [location.pathname]);
}
```

**MainButton — обязательно cleanup:**
```typescript
useEffect(() => {
  WebApp.MainButton.setText('Добавить к заявке');
  WebApp.MainButton.onClick(handleAdd);
  WebApp.MainButton.show();
  return () => {
    WebApp.MainButton.offClick(handleAdd); // без этого — двойные вызовы!
    WebApp.MainButton.hide();
  };
}, [handleAdd]);
```

**Хранение данных — стратегия:**

| Данные | Хранилище |
|---|---|
| Корзина (полная) | Сервер (PostgreSQL) |
| Корзина (кэш) | Zustand + localStorage |
| Избранное (только ID) | CloudStorage |
| Последние фильтры | CloudStorage |
| Верификация B2B | Сервер (по telegram user_id) |

**B2B авторизация через Telegram ID — правильно:**
```typescript
// backend: верификация HMAC перед выдачей JWT
function verifyTelegramInitData(initData: string, botToken: string): boolean {
  const params = new URLSearchParams(initData);
  const hash = params.get('hash');
  params.delete('hash');
  const dataCheckString = Array.from(params.entries())
    .sort(([a], [b]) => a.localeCompare(b))
    .map(([k, v]) => `${k}=${v}`).join('\n');
  const secretKey = createHmac('sha256', 'WebAppData').update(botToken).digest();
  return createHmac('sha256', secretKey).update(dataCheckString).digest('hex') === hash;
}
```

**Оптимизация изображений:**
- Thumb 200×200 WebP — для списка каталога (lazy loading)
- Medium 800×800 WebP — для карточки товара
- Оригинал — только для pinch-to-zoom по требованию
- CDN обязателен (Cloudflare R2 + трансформации)
- Виртуализация списка при > 50 товаров (`@tanstack/react-virtual`)

#### Подводные камни (новички не видят заранее)

**1. CloudStorage асинхронный без промисов — оберни сразу:**
```typescript
const cloudStorage = {
  get: (key: string): Promise<string | null> =>
    new Promise((res, rej) =>
      WebApp.CloudStorage.getItem(key, (err, val) => err ? rej(err) : res(val ?? null))

```

**2. Swiper zoom на iOS — отключить touchStartPreventDefault:**

```typescript
  allowTouchMove: false,

```

**3. Размер бандла — импортировать только нужные модули Swiper:**

#### MVP vs Полная версия

**MVP (2–3 недели) — проверить спрос:**

| Экран | Что делаем |
|---|---|
| Каталог | Список, базовый фильтр по типу |
| Карточка | Фото, описание, цена, кнопка |
| Корзина | Список позиций, итог |
| Заявка | Имя + телефон + комментарий |

Бэкенд MVP: Google Sheets API или Notion. Бот уведомляет менеджера.
Не делаем: верификация B2B, история, избранное, галерея с зумом.

**Полная версия — по итерациям:**
1. Верификация B2B + JWT + PostgreSQL
2. Галерея с зумом + CDN + WebP
3. История + профиль + серверная корзина
4. Избранное + фильтры с сохранением
5. Виртуализация + оптимизация бандла

### Общий список рекомендаций

**UX — приоритетные действия:**
1. Карточка товара — самый важный экран, делай её идеальной первой
2. Свотчи цветов минимум 32×32px, группируй цвета одной ткани в одну карточку
3. Сохраняй фильтры при возврате назад — критично для UX
4. Прямой ввод метража + валидация кратности в реальном времени
5. Главная как у B2C не нужна — открывай сразу Каталог

**Маркетинг — приоритетные действия:**
1. Каталог без регистрации — барьер входа должен быть нулевым
2. Формулировка "Отправить заявку на расчёт" вместо "Оформить заказ"
3. Тревожный счётчик остатков + перевод метров в единицы изделий
4. Имя и фото персонального менеджера в профиле клиента
5. Автоответ на заявку с временем реакции

**Разработка — приоритетные действия:**
1. Начни с MVP на Google Sheets, не трать время на полный бэкенд сразу
2. Верификация HMAC initData — с первого дня, не "потом добавим"
3. BackButton — один обработчик в Layout, не в каждом компоненте
4. Swiper — только нужные модули, иначе бандл > 200KB
5. CloudStorage оберни в промисы сразу

## Вывод

Ниша Telegram Mini Apps для оптовых тканей **практически пустая**. Большинство
конкурентов застряли на уровне "канал с фото + PDF-прайс" или примитивного бота
с кнопками без корзины и фильтров.

Полноценный Mini App с:
- галереей и зумом для фактуры ткани
- фильтрами по составу/плотности/ширине/цвету
- живыми остатками в метрах и рулонах
- корзиной с автократностью и заявкой менеджеру
- личным кабинетом с историей и повтором заказов
- запросом образца одной кнопкой

...будет выгодно выделяться на фоне **всех** игроков в нише и закрывать
реальные боли оптового закупщика тканей.
